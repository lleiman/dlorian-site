# Инструкции для Claude Code

Портфолио работ из Midjourney. Фронтенд — чистые HTML, CSS и JS без сборки
и фреймворков, как в `rubens-site` и `synopsis-site`. Бэкенд появился
позже, ради голосов и комментариев.

## Бэкенд

Раньше сайт был статикой на Caddy. Голоса и комментарии требуют состояния,
поэтому `Caddyfile` удалён, а статику и API отдаёт один процесс на Flask
(`server/app.py`, gunicorn в 3 воркера). Один контейнер, никакого прокси
между ними.

Данные лежат на томе Railway, смонтированном в `/data`: `site.db` (SQLite)
и `uploads/` с картинками из комментариев. **Без тома они переживут ровно
один деплой** — том уже создан, не отцеплять.

Ручки:

    GET  /api/summary              счётчики по всем работам разом
    GET  /api/mine                 что отметил этот браузер
    POST /api/vote                 {work, dir} — dir 1, -1 или 0 (снять)
    GET  /api/comments?work=N      список
    POST /api/comments             multipart: work, body, name, photo
    GET  /uploads/<файл>           картинки из комментариев
    POST /api/admin/comment/<id>   {action: approve|hide|show|delete}
    GET  /api/admin/pending        что ждёт проверки

Админские ручки требуют заголовок `X-Admin` с токеном из переменной
`ADMIN_TOKEN`; без токена отвечают 404, а не 403 — чтобы не подсказывать,
что они есть. Сам токен лежит в `_select/admin-token.txt`, в образ он не
попадает.

Что защищено и почему:

- **Фото ждут одобрения** (`PHOTOS_NEED_APPROVAL=1`). Открытая загрузка
  картинок на публичный адрес — это приглашение для мусора и хуже. Текст
  при этом публикуется сразу, ждёт только фото. Выключается переменной,
  но подумай дважды.
- **Картинка пересобирается заново** через Pillow. Так из файла уходят
  EXIF и всё, что могли дописать в конец под видом картинки; «текстовый
  файл с именем .jpg» отсекается на разборе.
- **Список отдаваемых путей закрыт** (`OPEN_DIRS`, `OPEN_FILES`). В боевом
  образе в `/srv` и так нет лишнего, но при запуске с `SITE_DIR` на папку
  проекта без этого списка уехали бы исходники сервера и `_select` с
  путями к оригиналам на диске.
- **Не больше 5 комментариев с адреса за 10 минут.**
- Номер работы сверяется со списком из `series.json` — иначе в базе
  копился бы мусор по любым id.

Комментарии рисуются только через `textContent`, никогда `innerHTML`:
тексты чужие.

## Откуда берётся сайт

Страницы не пишутся руками, а генерируются скриптами из `_build/` по данным
в `_select/`. Правка вёрстки — в `_build/pages.py`, потом перегенерировать.
Правка стилей — прямо в `assets/css/style.css`, он не генерируется.

Конвейер целиком, по порядку:

1. `_build/build_contact.py` — находит на диске файлы `Dlorian_*`, делает
   превью и `_select/manifest.json` (номер, путь, промпт, размеры, тип).
2. `_build/build_sheet.py` — локальный контактный лист `_select/index.html`.
3. `_build/build_artifact.py` — тот же лист как самодостаточная страница со
   встроенными превью, публиковалась артефактом для отбора с телефона.
4. `_build/series.py` — раскладывает отобранное по сериям в `_select/series.json`.
5. `_build/covers.py` — выбирает обложки в `_select/covers.json`: кадр и,
   если в серии есть видео, ролик для главной.
6. `_build/assets.py` — пережимает оригиналы в `assets/`.
7. `_build/montage.py` — **больше не используется.** Склеивал ролик для
   первого экрана, но исходные видео всего 832×464 (31 шт) и 624×624
   (14 шт): растянутые на всю ширину, да ещё после трёх пережатий
   (оригинал → лента → нарезка → склейка), они давали кашу. Первый экран
   теперь слайдшоу из кадров в честных 1600 px. Скрипт оставлен на случай,
   если ролик понадобится где-то ещё; `hero.mp4` из ассетов удалён.
8. `_build/notes.py` — заводит `_select/notes.json` с текстами между работами.
9. `_build/pages.py` — собирает `index.html` и `s/*.html`.

## Что где лежит

- `_select/manifest.json` — все 390 найденных работ.
- `_select/series.json` — 334 отобранные, разложенные по 11 сериям.
- `_select/covers.json` — какая работа обложка какой серии.
- `assets/img/NNN.jpg` — 1600 px, для просмотра во весь экран.
- `assets/thumb/NNN.jpg` — 760 px, для обложек и мобильного `srcset`.
- `assets/vid/NNN.mp4` + `assets/poster/NNN.jpg` — видео и их постеры.

Номер `NNN` — это `n` из манифеста, сквозной по всему архиву. По нему
всегда можно найти оригинал: `manifest.json` → поле `file`.

## Чего не делать

- Не добавлять npm, бандлеры, React, Tailwind.
- Не трогать `_select/` руками — это выход скриптов.
- Не убирать `?v=` из ссылок на css и js в `pages.py`. Caddy отдаёт статику
  с длинным кешем, и без версии правки стилей не доедут до тех, кто уже
  открывал сайт. Поменял css — подними `VER` в `pages.py`.
- Не ставить `display:inline` на `.card .frame`. Это `<span>`, а на
  инлайновом элементе `aspect-ratio` и `overflow` не работают — кроп 3:2
  молча ломается, обложки едут по высоте.
- Не включать автоплей всем видео сразу. Их 45 в лентах плюс 9 обложек
  серий и монтаж на первом экране; всё, что помечено `data-auto`,
  запускается по `IntersectionObserver` только когда попало в кадр, иначе
  это выбивает трафик и батарею на телефоне. При
  `prefers-reduced-motion` не запускается вообще, остаются постеры.

- Не растягивать первый экран на всю высоту. `min(72vh, 720px)` — чтобы
  под монтажом выглядывала первая серия и страница читалась как
  портфолио, а не как заставка.

- Не красить кнопки и счётчики в `--faint`. На чёрном он даёт контраст
  **1.85:1** при норме 4.5:1 — для тихой подписи сойдёт, для кнопки,
  которую надо найти и нажать, нет. Для функционального слоя есть
  `--act` (6.1:1). Номера кадров и подвал намеренно остаются тихими.

- Не делать кнопки меньше 44×44. Были 37×22 — на телефоне мимо.

- Не отдавать HTML с длинным кешем. Страницы пересобираются при каждом
  деплое; неделя кеша означала бы, что посетитель неделю видит старое.
  `html_response()` ставит `no-cache`, ассетам — год, css и js — неделю
  (они версионированы через `?v=`).

- Не убирать `cursor: zoom-in` с `.work`. Это единственный намёк, что
  кадр открывается во весь экран.

- Не открывать панель отзывов развёрнутой на узком экране. На 375×812 она
  занимала 37% высоты, а сама работа — 24%: пустая форма комментария была
  крупнее картины. Ниже 900 px панель открывается в режиме `compact`
  (только пальцы, 58 px), комментарии разворачиваются по `[отзывы]`.
  На широком экране по-прежнему `full` сразу — так просил автор.

- Числительные склонять через `plural()` в `pages.py`. «334 работ» и
  «62 работ» — неправильно, нужно «334 работы», «62 работы», «30 работ»,
  «41 работа».

## Чего исправить нельзя

Широкий кадр 16:9 на вертикальном телефоне занимает около 24% высоты
экрана, даже растянутый на всю ширину. Чёрные поля сверху и снизу — это
геометрия, а не ошибка вёрстки. Единственное решение — квадратные или
вертикальные кадры, то есть другой исходный материал.

## Превью ссылок и «поделиться»

`_build/og.py` рисует альбомные карточки 1200×630 в `assets/og/`: одну для
главной и по одной на серию. Кадр во всю ширину, затемнение снизу, поверх
имя и подпись моноширинным. Раньше `og:image` не было вовсе — ссылка на
сайт в мессенджере показывалась голым текстом.

`og:image` обязан быть абсолютным, поэтому в `pages.py` есть `SITE_URL`.
**Если сменится домен — поменять там же**, иначе превью отвалятся.

Кнопка `[поделиться]` в открытом кадре собирает такую же карточку прямо
в браузере через canvas. На телефоне уходит в системное «поделиться»
(`navigator.share` с файлом) — оттуда в инстаграм; на десктопе системного
диалога нет, поэтому картинка скачивается, а ссылка кладётся в буфер.

Тонкости, которые легко сломать:

- Картинка берётся с того же origin, иначе canvas «пачкается» и `toBlob`
  перестаёт работать. Не подставлять сюда внешние адреса.
- Перед отрисовкой ждём `document.fonts.load` — иначе подпись уедет
  в системный моноширинный.
- Межбуквенный интервал: `ctx.letterSpacing` есть не везде, поэтому
  оставлен запасной путь посимвольной отрисовки.

Карточка в двух размерах, выбор в превью: **сторис 1080×1920** (по
умолчанию) и **лента 1080×1350**. Карточку не 9:16 инстаграм в сторис
обводит своим размытием, и выглядит это криво — поэтому размер выбирается
заранее, а не подгоняется постфактум.

Полосы сверху и снизу **не фиксированы**: кадр вписывается в доступную
высоту, остаток делится между полосами поровну, подпись центрируется внутри
своей полосы. При жёстком окне между кадром и текстом оставался ничейный
зазор — у широких работ особенно заметный.
Работа вписывается целиком, без обрезки; фон — размытая и затемнённая копия
её же, поэтому всегда в её цветах. Текст сверху и снизу.

**Прямой отправки в инстаграм из браузера не существует, и не появится.**
Инстаграм не регистрируется приёмником файлов в системном «Поделиться» и
принимает картинки только из галереи; схема `instagram-stories://` доступна
лишь зарегистрированным приложениям Facebook. Поэтому после сборки карточка
показывается в превью с кнопкой «сохранить»: человек кладёт её в галерею и
выкладывает из приложения. Не пытаться «починить» это — чинить нечего.

Ссылка в подписях инстаграма не работает вообще: он их вырезает. Адрес
сайта живёт в шапке профиля, карточка работает как приманка.

## Поиск, ссылки и подписка

Сайт **открыт к индексации** (запрет `noindex` снят), есть `robots.txt`,
`sitemap.xml` на 347 адресов и `canonical` на каждой странице.

Важно понимать, зачем это. Портфолио не находят через поиск — портфолио
показывают. Единственный сценарий, где поиск важен: человек увидел работу,
запомнил имя, вбил его. Раньше эта нить рвалась гарантированно.

**У каждой работы свой адрес** — `/w/NNN.html`. Было 13 страниц, стало 347.
Это и возможность дать ссылкой конкретный кадр, и материал для поиска.
`og:image` там — сама работа: отдельные карточки на 334 страницы весили бы
десятки мегабайт и ничего бы не добавили.

Пути в меню считаются как `../s/` при `depth=1`: страницы работ лежат в
`/w/`, и прежний расчёт «от `/s/`» вёл там в никуда.

**Подписка** (`POST /api/subscribe`, таблица `subs`) — единственный способ
владеть аудиторией, а не арендовать её у площадки, которая может выключить
охват. Список: `GET /api/admin/subs`.

**Счётчик** (таблица `hits`, `GET /api/admin/stats`) считает по дню,
странице и домену-источнику. Ни адресов, ни кук, ни личных данных: от
реферера берётся только домен. `note_hit` никогда не роняет выдачу —
счётчик не та вещь, ради которой стоит показать посетителю ошибку.

**При смене домена** поменять `SITE_URL` в `pages.py`: от него зависят
`canonical`, `og:image` и `sitemap`.

## Админка (Ctrl+Shift+E)

Правит те же json, из которых собирается сайт, и просит сервер пересобрать
страницы тем же `pages.py`. Данные лежат на томе (`/data/content`), поэтому
правки переживают деплой; исходники запечены в образ и копируются на том
только при первом запуске.

Панель контекстная: на главной — манифест и показы, на странице серии —
заявление, тексты между работами, порядок и состав работ, цены; на витрине —
имена, подписи, порядок. Токен из `ADMIN_TOKEN` хранится в браузере.

Что легко сломать:

- **Собранные админкой страницы лежат на томе и в выдаче главнее образа.**
  Поэтому сервер при старте сверяет время `pages.py` в образе с меткой
  `/data/site/.built` и пересобирает, если образ новее (`ensure_built`).
  Без этого деплой обновлял бы только стили, скрипт и картинки, а вёрстка
  страниц навсегда осталась бы такой, какой её собрал прежний генератор —
  ровно это однажды и произошло, HTML застрял на `v=22`. Не убирать.

- Любая новая html-страница должна быть и в `OPEN_FILES` в `server/app.py`,
  и скопирована в Dockerfile. Дважды на этом обжигались — витрина и показы
  отдавали 404 только на бою.
- `pages.py` берёт пути из `SITE_OUT` и `CONTENT_DIR`. Не возвращать
  хардкод: без этого сервер не сможет пересобрать сайт.
- Запись `series.json` проверяется на сервере: пустая структура и
  несуществующие номера отбиваются. Не убирать — битый файл уронит сборку
  всего сайта.

## Цены и показы

`prices.json` и `shows.json` заводятся пустыми, и это осознанно: цена
показывается только у той работы, которой её задали, а страница показов и
ссылка на неё в шапке не появляются, пока нет ни одной даты. Портфолио с
ценником на каждой работе мгновенно читается как магазин.

Цена — мелкая строка рядом с номером кадра, как этикетка в галерее.
Статусы: `available` (показывается сама цена), `request` («цена по
запросу»), `reserved` («бронь»), `sold` («продано», зачёркнуто).

## Витрина (deck.html)

Одна работа на экран, перелистывание стрелками, клавишами и свайпом,
прокрутки нет — модель ecstasyboi.com. Она работает **только при малом
числе работ**: 16 можно перелистать, 334 нельзя, это 334 нажатия. Весь
архив остаётся на главной и страницах серий.

Состав и имена — в `_select/deck.json`. Засеян 16 работами по оценке из
`covers.py`, имена пустые: их может дать только автор. Пока имени нет,
работа подписывается серией и номером — `'KISSING · 158'`.

    {"n": 158, "series": "KISSING", "name": "БЛИЗКО",
     "note": "midjourney, серия из 41 кадра"}

`deck.py` не перезаписывает существующий файл. Чтобы пересеять — удалить.

Что легко сломать:

- `deck.html` должен быть и в `COPY` в Dockerfile, и в `OPEN_FILES`
  в `server/app.py`. Забыть любое — страница отдаст 404 только на бою.
- Подвал на витрине скрыт: на странице без прокрутки он забирал низ
  экрана у самой работы.
- Грузятся только текущий кадр и соседние. Не ставить `src` всем сразу —
  это 16 картинок на входе.

## Первый экран

Слайдшоу лучших работ, порядок — по лайкам (`up - down`, по убыванию,
до 10 кадров). Пока голосов мало, список добирается запасным порядком из
`_select/best.json`: его пишет `covers.py` по той же оценке яркости и
контраста, не больше двух работ из серии, иначе первый экран покажет одну
тему.

Первый слайд отрисован сервером в HTML, не скриптом: страница должна быть
видна с первого кадра, а не ждать загрузки счётчиков. Скрипт достраивает
остальные и переставляет вперёд то, что набрало голоса, — и ждёт события
`load` первой картинки, иначе на её месте мигает чёрное.

## Порядок серий на главной

Серии с живой обложкой уходят вниз (`names.sort` в `pages.py`): верх
главной должен быть спокойнее. Обложки без видео есть только у KISSING и
TATTOO, поэтому спокойных полос ровно две — если нужно больше, надо
принудительно задать неподвижные обложки в `_select/covers.json`, убрав
у части серий ключ `vid`.

## Отбор

334 работы из 390. Сам отбор делал автор в контактном листе; 18 тем
выброшено целиком (аниме, киберпанк, собор, поэма, редакционные постеры,
корпоративное, зин-коллажи). Внутри оставшихся тем взято почти всё, поэтому
серии крупные и внутри много близких вариантов одной генерации — это
известно и осознанно.

Разбор по сериям — в `_build/series.py`, правила в списке `RULES`,
порядок важен: первое совпавшее правило выигрывает.

## Что не доделано

- **Контакты.** В `_build/pages.py` список `LINKS` пустой, поэтому блок
  ссылок в шапке и подвале не отрисовывается. Заполнить парами
  `("INSTAGRAM", "https://...")` и перегенерировать.
- **Имя.** Взято `DLORIAN` — по нику в именах файлов. Если нужно другое,
  менять `SITE_NAME` в `pages.py`.
- **Тексты серий.** Живут в `_select/notes.json`: `lead` — крупная строка
  под заголовком серии и в блоке на главной, `notes` — вставки между
  работами, они раскидываются по ленте равномерно и попеременно вправо и
  влево. Пока засеяны настоящими промптами; выдумывать цитаты за автора
  нельзя, поэтому промпт и подписан промптом.

  Формат записи решает, как текст покажется:

      "любая строка"                     → мысль автора: гротеск, без подписи
      {"kind": "prompt", "text": "..."}  → промпт: моноширинный, с подписью

  Человеческий текст и машинный набраны разными гарнитурами намеренно —
  так опечатка в промпте (`lamborginin`, `ugly ald lady`) читается как
  документ, а не как ляп вёрстки. Заменил объект на строку — подпись
  «промпт» пропала сама.

  `notes.py` не перезаписывает уже существующий `notes.json`: правки
  автора важнее пересборки. Чтобы пересеять с нуля — удалить файл.
- **WebP.** Картинки в JPEG, потому что в ffmpeg на этой машине нет
  `libwebp`, а `sips` в webp не умеет. `brew install webp` и пережать
  через `cwebp` — минус примерно 30% веса.

## Деплой

Railway, аккаунт `univercityofai` (AI UNI's Projects), проект `works-site`:

    railway up --service works-site

Заголовок `X-Robots-Tag: noindex` ставит сам сервер (`static_files`) —
пока это черновик. Когда сайт будет готов к показу, строку убрать.

Локально сервер поднимается так (Flask и Pillow нужны в окружении):

    SITE_DIR=$PWD DATA_DIR=/tmp/wsdata \
    SERIES_PATH=$PWD/_select/series.json \
    PORT=8877 ADMIN_TOKEN=testtoken python3 server/app.py
